Architecture overview

Factory Inventory Management System

A two-tier demo app. A Vue 3 single-page app talks to a FastAPI service over a small REST API. All data comes from JSON fixture files that are loaded into memory when the server starts. There is no database, there are no writes, and data resets on every restart.

Data flow: changing a filter

What happens when a user picks a warehouse in the filter bar on the Dashboard.

  1. FilterBar updates shared state

    The select writes to refs declared at module scope in useFilters. Because the refs are module-level singletons, every view reads the same filter state.

    client/src/composables/useFilters.js
  2. The view's watcher reloads data

    Each view runs watch() on the refs it cares about. Dashboard and Orders watch all four filters. Inventory, Demand and Backlog watch only warehouse and category. Spending watches only the time period.

    client/src/views/Dashboard.vue
  3. Filters are mapped to API params

    getCurrentFilters() returns { warehouse, category, status, month }. api.js drops any value of 'all' and builds the query string.

    client/src/api.js
  4. Parallel HTTP requests

    Dashboard sends four requests at once through Promise.all: summary, orders, inventory and backlog. Each one goes to http://localhost:8001/api/....

  5. Filtering in memory on the server

    apply_filters matches warehouse exactly and category and status case-insensitively. Then filter_by_month does a substring match on order_date; it also accepts Q1-2025 through Q4-2025. Inventory has no date, so the month filter is never applied to it.

    server/main.py
  6. Validation and response

    FastAPI checks each result against its Pydantic response_model, turns it into JSON and returns it. Summary and reports endpoints return plain dicts with no model.

  7. Reactive rendering

    The view puts the raw arrays in refs such as allOrders and inventoryItems. Computed properties then derive KPIs and chart series from them, and formatCurrency applies the active locale's currency.

    client/src/utils/currency.js

Things worth knowing

Observations from reading the code. They're useful context before you change anything.

Client calls missing endpoints

api.js defines task and purchase-order calls, but main.py has no routes for them. Tasks fail to load with an error that only shows in the console, so only the hardcoded tasks from useAuth appear.

Backlog view is orphaned

Backlog.vue exists and loads data, but it isn't registered in the router in main.js.

Reports bypasses api.js

Reports.vue imports axios directly with a hardcoded URL. The base URL is also hardcoded in api.js, and no env config is used.

Backlog count ignores filters

/api/dashboard/summary filters inventory and orders, but total_backlog_items always counts the full list.

Quarter support only on the server

filter_by_month accepts Q1-2025 through Q4-2025, but FilterBar only offers individual months.

Read-only, demo-grade server

Data lives in module globals, nothing is persisted, and CORS allows every origin with credentials. That's fine for a demo but not something to deploy as-is.
